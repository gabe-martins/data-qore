01 · Introduction

What DataQore does

DataQore compares two sources, Source A and Source B, using registered tables, an equivalent scope and a key that identifies each record. Each execution saves its own configuration and reports volume differences, key presence, identity integrity and value correspondence.

  1. Connections
  2. Catalog
  3. Comparisons
  4. Execution
  5. Comparison Quality
  6. Overview

A connection holds access to a source. A dataset registers a table or view. A comparison defines the rules between two datasets. A run executes those rules. You can reuse a saved comparison for manual and scheduled executions.

Quality needs context. Counts and key integrity cover the entire selected scope. Key presence, row equality and column equality describe the selected sample. A sample with 100% correspondence does not prove equality of entire tables.

The application has five metrics. Diagnostics and the quality target support interpretation; they do not create a composite quality score.

02 · Quick start

Run your first comparison

  1. Sign in with the email and password provided by an administrator. Replace a temporary password in Profile before using operational features.
  2. In Connections, choose New connection, enter source details, use Test connection and Save connection. Source setup requires Data Developer or Platform Administrator.
  3. In Catalog, choose the connection, catalog when applicable, and schema. Use Register dataset for each table and inspect its metadata.
  4. In Comparisons → New comparison, choose A/B, scope, columns, timezones, mapping, business key, sample and tolerances.
  5. Check Review. Save comparison only saves the definition; Save and run also queues an execution.
  6. Wait for the selected execution to finish. Runs also shows its technical status.
  7. Investigate the conclusion, denominators, dimensions, column differences and captured records in Comparison Quality.
  8. Monitor daily history in Overview and configure Schedules for recurring execution.

Results Viewers can start with existing results in Overview or Runs. Quality Managers can create comparisons and schedules using registered datasets.

04 · Monitoring

Overview and its tables

Overview summarizes active comparisons and saved history. Opening it neither starts comparisons nor queries source tables again.

Top indicators

  • Row Match Rate: weighted aggregate: sum matching rows and evaluated denominators rather than averaging percentages. The detail shows counts and coverage.
  • Quality target: the current environment-wide Row Match Rate minimum, attainment status and settings link.
  • Active comparisons: the number of active definitions, including how many have an evaluated latest result.
  • Requires investigation: comparisons with observed differences, inconclusive results or technical failures, shown separately.
Illustrative weighting example: 90/100 matching rows in one comparison and 10/10 in another produce 100/110 = 90.91%, rather than the simple average of 90% and 100%.

Choose a comparison, 7/15/30 days and a metric. Column Match Rate also requires a Column pair. Key Coverage retains both directions; Duplicate Key Rate retains both sources. Lower duplicate and volume-difference rates are better.

Each calendar day uses the last terminal execution in America/Sao_Paulo; today is partial. A later failure masks an earlier success that day. Days without evaluation remain gaps, never fabricated zeros or joined missing points. Pending executions do not erase the latest terminal result. The dashed target line applies the current target throughout the displayed period, without reconstructing past targets. The chart period filters history; it does not change the source scope of saved runs.

06 · Tables

Catalog and datasets

Data Developers and Platform Administrators can explore Source catalog. Choose a connection and schema; Databricks also requires a Unity Catalog. The source table lists Schema, Table / view and Action, with Type where applicable.

Register dataset records a reference to a table or view, without copying its population. Registered datasets shows name, type, location, metadata column count and Delete. Quality Managers read registered datasets without exploring or registering sources.

Open a dataset to see its location and column count. Column metadata shows Column, Type, Nullable and Primary key. Unknown means the metadata was not provided. Table details exposes additional source metadata when available.

07 · Setup

Configure a comparison in four steps

Comparisons offers search and a table showing Comparison, active/inactive State, available Row Match Rate and Latest run technical status. Open a name for quality and history, New comparison to create a definition or Edit to change one.

Step 1 — Sources and scope

Enter Name and choose Source A/B datasets. Equivalent scope supports:

  • All available dates: no temporal restriction; additional filters can still restrict the scope.
  • Fixed period: choose equivalent period columns, inclusive Start, exclusive End and Scope timezone. October 1 through November 1 includes all of October.
  • Previous complete units: choose complete hours, calendar days or months and a quantity. Safety delay subtracts minutes before resolving the closed window. Hours require timestamps; days/months also accept DATE. The window freezes when queued.

Scope timezone uses IANA names such as America/Sao_Paulo. Set Naive timestamp timezone A/B for period columns without stored timezone information. Bounds follow [start, end).

Add filter / batch creates equivalent criteria with matching A/B columns, an operator and value. Criteria combine with AND. Operators are Equals, In a list, Greater than or equal, Less than, Is null and Is not null. Lists use one value per line; filter decimals use a dot. There is no free SQL input.

Step 2 — Columns and timezones

Compare selects participating columns. Explicitly excluded columns do not contribute to row/column correspondence; counts and key validation still cover the scope. Exclude both sides of a pair to remove it entirely. A remaining unpaired column blocks full row approval. Identity columns cannot be excluded.

Timestamp timezone interprets each timestamp without timezone, even without a temporal filter. Choose the timezone represented by stored values, not the browser location. Stored offsets retain their instants, compared in UTC. Ambiguous or nonexistent local times may remain not evaluated. Window timezone and timestamp interpretation serve different purposes and must be consistent.

Step 3 — Identity and sample

Check Source column A / Comparison column B in Column mapping & identity. Manual pairs take precedence; remaining unambiguous matching names are paired ignoring name case. Text values remain case-sensitive and preserve whitespace.

Mark Business key on one or more pairs to define a simple or composite identity. Keys need compatible supported types, no null components and uniqueness throughout the scope. Floating-point values cannot serve as identity. Without an explicit key, the engine searches compatible PK/non-null UNIQUE metadata. Execution validates the entire scope; invalid identity prevents alignment without silently choosing a different key.

Configure Number of keys or Percentage of larger scope and optional Seed. See sampling limits below.

Absolute tolerance uses field units. Relative tolerance (fraction) uses fractions: 0.01 means 1%; 1 means 100%. A dot or comma decimal is accepted without thousands separators. Zero requires exact numeric equality.

|A − B| ≤ max(absolute tolerance, relative tolerance × max(|A|, |B|))
Illustrative example: A = 100, B = 101, relative tolerance 0.01 and absolute tolerance zero. Difference 1 is within relative allowance 1.01. This tolerance concerns numeric values, not the percentage of differing rows. Text remains exact.

Capture budgets sets Maximum cells (both sources) and Maximum captured bytes. These operational limits differ from key count; oversized requests are rejected rather than silently reduced.

Step 4 — Review

Review requested keys, provisional scoped counts, Comparison key, exclusions and timestamp interpretation. Back lets you correct rules. Save comparison saves without running; Save and run also queues. Source changes between preview and execution can produce different counts.

Edits apply to future runs. Each run retains its frozen window, column pairs, exclusions, timezones, tolerances and seed; editing a definition does not rewrite history.

08 · Analytical reach

Sampling and coverage

The engine scans eligible keys on both sources, deterministically selects positions from their union and fetches the same keys on A/B. This finds one-sided records; it does not take independent samples.

  • Number of keys accepts 1–10,000 integer keys; the form defaults to 1,000.
  • Percentage of larger scope accepts greater than zero through 100, based on the larger complete A/B row count, rounded up. The requested sample must still stay within 10,000.
  • Seed is an unsigned 64-bit decimal integer. Leave blank to generate at queue time. The same seed, rules and eligible key set reproduce selection; values may have changed.
Illustrative example: A has 20,000 scoped rows and B has 30,000. Requesting 10% selects up to 3,000 keys based on 30,000, not 10% of the union. The actual sample is smaller if the union has fewer keys. A 50% request would need 15,000 keys and is rejected.
Different denominators
InformationMeaning
Scoped population A / BAll rows satisfying the period and filters on each source.
Selected union-key positionsThe actual selected union-key sample before unavailable evaluation is considered.
Evaluation coverageEvaluated / selected positions × 100. Full sample evaluation does not mean full-population comparison.

Selected positions / larger scoped row count is not a union sampling fraction. No statistical confidence interval is inferred.

The 10,000 comparison cap does not cap all source work. Counts, key validation and selection scan the complete scope. Stable local reads do not synchronize distinct databases. Check consistency warnings.
09 · Metric reference

The five metrics: formulas, scope and interpretation

Rates range from 0–100%, except volume difference relative to A, which can exceed 100%. Always read numerator, denominator, not evaluated and coverage. An empty denominator is not 100%. A zero can be healthy or problematic depending on the metric.

Metrics in tables and details
MetricCalculationScopeInterpretation
Row Count MatchCounts A/B; signed B − A; absolute |B − A|; 100 × |B − A| / A.Entire scope.Equal counts requires A = B. Zero percentage difference is best; equal volume does not establish equal content.
Key CoverageA → B: 100 × common keys / sampled keys observed in A. B → A uses B as denominator.Selected sample; two directions.Higher is better. One direction can be 100% while the other is lower.
Duplicate Key Rate100 × excess duplicate rows / rows with no null key components, per source.Entire scope, A/B separately.Lower is better. Null-key rows are reported separately.
Row Match Rate100 × entirely equal records / evaluated positions.Selected sample.Higher is better. Every included field must match; missing records count as differences.
Column Match Rate100 × equal values / evaluated positions for each pair.Selected sample, per pair.Higher is better. Reveals problematic fields without averaging pairs into a combined score.

Row Count Match

A = 1,000 and B = 1,100 gives signed +100 and 10% absolute difference. Reversing sources changes the denominator. A = 100 and B = 300 gives 200%. If A = 0 and B is positive, the percentage is undefined while counts still show the difference. Two empty tables have equal volume but no record sample to evaluate.

Key Coverage

If A contains 100 selected observed keys and B contains 80, all found in A, the 80 common keys produce A → B = 80% and B → A = 100%. Presence does not establish equal record values. Invalid identity may make alignment and rates unavailable.

Duplicate Key Rate

Three rows sharing one key contribute two excess rows. If all other keys are unique and there are 100 non-null-key rows, the rate is 2%. Duplicate groups counts repeated key groups; Null key rows counts rows with at least one null component. Repeated values outside the comparison key are not duplicate identity.

Row Match Rate

A position matches when all included values agree under frozen types, timezones and tolerances. A record present on only one side differs. A proven difference prevails over another unknown field; without a proven difference, partially unknown positions remain outside the denominator. Unpaired or incompatible columns prevent full approval.

Illustrative example: of 1,000 selected positions, 940 match, 40 differ and 20 cannot be evaluated. Row Match Rate is 940/980 = 95.92%; evaluation coverage is 980/1,000 = 98%. Even above a 95% target, evaluation is partial and differences were observed.

Column Match Rate

Each pair has its own equal, evaluated, different and not evaluated counts. Many high column rates do not make an entire row equal. Missing records count as differences where evaluable; unknown values are never assumed equal. Explicitly excluded columns do not participate.

Calculation details explains formulas, scope, denominators and tolerances. NULL, empty strings, whitespace, absent records and unavailable values remain distinct.

10 · Diagnosis

Investigate a selected execution

Choose Selected execution → Execution on the comparison page. Its run_id remains pinned in the URL while browsing history pages. Confirm that selection before investigating or sharing a link.

Execution information shows technical status, sources, requested date/duration, identity, scope, exclusions, timestamp interpretation, tolerances and sampling seed/strategy. Duration can remain Pending until required timestamps are available.

Analytical conclusions
ConclusionMeaning
compatible_in_sampleVolume/identity requirements passed and the complete sample was evaluated without differences. It does not certify full-population equality.
difference_observedA volume, identity or record difference was proven. High correspondence rates may coexist with it.
inconclusiveRequired evidence is insufficient to conclude.

Succeeded means processing published a result. Target met means Row Match Rate meets its reference with complete evaluation; other discrepancies still matter.

Quality dimensions and coverage

Expand Volume for counts, Key Coverage for directional presence, Consistency for correspondence, Integrity for duplicate/null key components and Technical Compatibility for unpaired/incompatible fields. Compatibility is a technical diagnostic without a percentage.

Passed indicates a satisfied requirement; Attention highlights volume/content differences; Critical highlights identity, absence or structural blockers; Not calculated indicates insufficient evaluation. Calculation availability and validation status are separate. Analysis coverage shows A/B populations, selection size and evaluation coverage. Expand Consistency and limitations for source warnings.

Column analysis

Search columns, filter Column status and use Order columns for most differences/unknowns, name or lowest match rate. Pages contain 50 pairs. Column A / B expands types and calculations; Match rate shows the individual rate and coverage; Differences separates divergent and unknown values; Status shows validation. Inspect column filters captured evidence to differing or unavailable cells in that pair and requires available evidence.

Divergence diagnosis

Cards separate Missing in source A/B, Different paired records, Unclassified row positions, Duplicate key groups, Rows with null key components and Unpaired or incompatible columns. Categories may overlap; never add their counts as distinct records. Inspect records applies a captured-record filter when supported. Full-scope identity and schema violations may have only aggregate diagnostics.

11 · Evidence

Inspect and export records

Record inspection reads frozen evidence without querying sources again. Captured evidence can be smaller than the evaluated sample. Capture is limited to 10,000 positions and 32 MiB per run, prioritizing differences and missing records when necessary.

Individual evidence availability
StateMeaning
Captured sample / availableCaptured positions are available, not the full population.
Partial captureCapture limits were reached. Tables and downloads cover stored positions only without changing aggregates.
Not capturedA historical run has aggregates only; evidence is not reconstructed.
Expired30-day retention elapsed; aggregate metrics and configuration remain available.
UnavailableConsultable evidence could not be captured. Read the reason, such as invalid identity.
  1. Record state filters All records, Equal, Different, Only source A/B or Not evaluated.
  2. Affected column selects records with a differing or unavailable cell in that pair.
  3. Exact key requires a JSON array of every component in the displayed order, for example ["123"] or ["BR", "123"]. Preserve case/whitespace and use strings for large numeric precision. Select Search key.
  4. The table shows Key, State, Affected fields and Details. Inspect record opens Column A/B, Source A, Source B and State side by side. Pagination uses 50 records.
  5. Clear filters resets the search. No matching captured records does not prove population-wide absence.

NULL, Empty string, Whitespace, Record / column absent and Unavailable remain distinct. Compared as shows the normalized comparison representation when applicable.

Two downloads

  • Download captured records exports JSON matching current filters across all matching captured pages, with its capture manifest. It is not a full-population export.
  • Download result on the run page exports aggregate results and technical details without replacing the individual evidence download.

Evidence is stored encrypted, and record access/exports are audited. All result readers can export available evidence. Downloads may contain business values; application retention does not delete previously downloaded copies. JSON keys, source values and technical identifiers remain unchanged when switching interface language.

12 · Executions

Runs and technical states

Run history filters by Execution state. Comparison links to the run and shows the beginning of its ID. Requested shows request time, Duration shows elapsed processing time when available, State is technical and Conclusion is analytical. Pending runs refresh periodically.

Technical state is separate from data quality

13 · Automation

Schedules

New schedule targets an existing saved comparison. Enter Schedule name and Comparison. Search schedules filters by name. A comparison_id link can limit the list; All schedules removes that context.

  1. Guided offers Every N minutes, Hourly, Daily, Weekly or Monthly with corresponding interval/time/day fields.
  2. Cron expression accepts five fields: minute, hour, day of month, month, weekday. There are no seconds or shell commands.
  3. Verify Timezone, Effective cron and the next three occurrences.
  4. Set Schedule enabled and Save schedule after the preview validates.
Examples in the selected timezone
ExpressionExecution time
*/15 * * * *Every 15 minutes.
0 * * * *Hourly at minute zero.
0 8 * * *Daily at 08:00.
30 9 * * 1-5Monday–Friday at 09:30.
0 8 1 * *First day of each month at 08:00.

If both day-of-month and weekday are restricted, either may match. Months without a requested day are skipped. Timezone transitions apply. Switching from a custom cron to Guided replaces it with the guided selections.

Cards show cron, timezone and Next occurrence. Edit changes the schedule. Pause / Resume controls future occurrences without cancelling an already queued run or delivery in progress.

Dispatch history

Columns show Scheduled time, Delivery, Attempts, Details and Run. Pending awaits delivery, dispatched was delivered to the queue, skipped was omitted and failed means delivery failed. Open run shows processing and analysis; dispatched is not succeeded or analytical approval.

A comparison already queued/running is skipped with comparison_busy. Transient deliveries retry up to five times. Controller, engine and worker must be running; a stopped worker leaves runs queued. After downtime, one overdue occurrence is considered rather than replaying all missed times. Deactivating the creator does not automatically pause environment schedules.

Settings and administration

Personal → Profile

Account details shows Name, Email, Role and Group. Change password requires Current password, New password and confirmation, 12–128 characters. Changing it signs out all sessions. Temporary passwords must be replaced before operational access.

Personal → Language

Select English or Português (Brasil). English is the initial default. The choice applies immediately, persists in this browser and synchronizes its tabs. It also applies to sign-in, this manual and its HTML download. Blocked storage keeps the choice only in memory. Source names/values, technical identifiers and API payloads are not translated. The language page remains available while a temporary password change is required.

Personal → Appearance and Theme

System follows the device, Light and Dark select a fixed theme. The preference is saved on this browser and shared with the user-menu Theme control. The integrated manual uses the same theme; a standalone manual follows the device preference.

Quality → Quality target

Enable quality target, enter Minimum Row Match Rate (%) from 0–100 with up to four decimals and Save target. The initial target is 95%; disable and save to remove it. Results Viewers read it; Quality Managers, Data Developers and Platform Administrators can update it.

  • Target met: rate meets the minimum with complete evaluation.
  • Below target: calculated rate falls below the minimum.
  • Partial · above target: meets the minimum among evaluated positions, with unknown positions remaining.
  • Not evaluated / Unavailable: no usable calculation.
  • Target disabled: the reference is switched off.

The target is environment-wide, applies only to Row Match Rate and changes no formulas, tolerances or saved conclusions. Overview applies the current target throughout history.

Administration → Groups

Platform Administrators create groups with Name, Description and one fixed Access profile. Each user belongs to exactly one group; there are no individual overrides. Changing a group profile revokes member sessions; renaming does not change permissions. Edit group updates it. Delete group requires no members, including inactive users. The last active administrator cannot lose administrative access.

Administration → Users

New user requires name, email, group, Active status and a 12–128-character Temporary password. Save and deliver the password through an approved external channel; no automatic email is sent. The table shows name, email, group/profile, activation and mandatory password change.

Edit user changes details, group or activation. Reset password sets a temporary replacement, revokes sessions and requires another change. Revoke sessions signs out existing sessions. Group reassignment/deactivation also revokes access. Users are deactivated, not permanently deleted. The final active administrator is protected against demotion/deactivation.

Administration → Security audit

The paginated table shows Time, Actor (or Unauthenticated), Action, Resource, Outcome and Request ID. It tracks administrative/access events rather than source differences or per-run query audit.

Help → User manual

15 · Lifecycle

Deactivation and deletion

Deletion dialogs check current dependencies. Cancel returns; Retry dependency check or Refresh dependencies rechecks failed or blocking conditions.

  • Connection: registered datasets and linked comparisons block deletion. Deactivate preserves configuration/history and prevents new operations needing an active connection.
  • Dataset: current or historical comparisons block deletion, even inactive ones. Allowed deletion removes registration without deleting the source table or its rows.
  • Comparison: current/historical schedules block deletion, including paused schedules. Queued/running runs also block it. When allowed, Delete comparison and run history permanently removes the definition, runs, results and evidence.
  • Group: deletion requires no members, including inactive users. User accounts can be deactivated rather than deleted.
Deactivating a comparison preserves configuration and results. Deleting its history is irreversible in the UI. Check the name and displayed quantities before confirming.
16 · Practical help

Questions and troubleshooting

Does succeeded mean approved data?

No. Read Comparison Quality: succeeded is technical success, difference_observed proves a discrepancy, inconclusive means insufficient evidence. Target attainment is independent.

Why can a 100% Row Match Rate coexist with differences?

Check volume, null/duplicate identity, both coverage directions, columns, unknowns and the selected run. A rate describes evaluated sample positions, not all population rows or every quality dimension.

Is a 0% rate a failure?

Zero duplicate excess and zero volume difference are healthy when evaluated. Zero row/column correspondence with a positive denominator means no evaluated positions matched. Unavailable is not zero.

Why was the key rejected?

Check supported compatible types, non-null components and uniqueness over the complete scope. Choose a suitable simple/composite business key, refresh changed metadata and run again. A larger sample cannot repair invalid identity.

Why do apparently equal dates differ?

Verify types, offsets and Timestamp timezone per column. Stored UTC and local times need their actual interpretations. Window timezone filters dates; timestamp timezone interprets values.

The sample exceeds a limit.

Percentage is rounded up from the larger A/B scope. Reduce the percentage/scope or use up to 10,000 keys. Check cells, bytes and included columns. Oversized requests are not silently reduced.

Why is old record evidence unavailable?

Historical runs may have aggregates only; captured evidence expires after 30 days. It is not reconstructed by reading current sources. A new run records a new state.

Why are chart points missing?

Unavailable days are gaps. A later terminal failure masks earlier success for the same day. Inspect Runs to see the full history.

A run stays queued or a schedule did not deliver.

Ask the administrator to check the worker/services. Open Dispatch history for comparison_busy, inactive source/comparison or delivery errors. Recovery does not replay every old occurrence.

A screen is missing or access is denied.

Check your group/profile and any required temporary-password change. Quality Managers use registered datasets, Data Developers manage sources and Platform Administrators manage access. Ask an administrator to review membership.

What should I include in a support request?

Provide page, comparison name, run ID, time/timezone, technical status, code/message and request ID. For discrepancies, include the metric, numerator/denominator and coverage.
